# Purpose

Проектировать и создавать задачи Jira на основе проанализированных требований (результата работы Skill requirement-review), обеспечивая декомпозицию функциональности на атомарные, проверяемые и независимо реализуемые задачи с корректными связями, критериями приемки и достаточным контекстом для разработки.

# Inputs

Для применения skill необходимы:

- структурированный результат анализа требований от Skill requirement-review
- список выявленных функциональных требований
- бизнес-правила и ограничения
- критерии приемки
- зависимости в требованиях
- найденные неоднозначности и противоречия
- зафиксированная отсутствующая информация
- выявленные риски
- контекст проекта (структура проекта Jira, эпики, существующие задачи)
- настройки подключения к Jira (доступ, права на создание задач)

# Procedure

1. Проверить полноту входных данных (наличие результата requirement-review, отсутствие блокирующих противоречий)
2. Определить границы поставки (scope) на основе подтвержденных функциональных требований
3. Выполнить декомпозицию требований на задачи по принципу атомарности и независимой проверяемости
4. Определить тип каждой задачи (feature, improvement, technical, research, bug)
5. Сформировать для каждой задачи:
    - заголовок по шаблону
    - описание с контекстом и ссылками на требования
    - критерии приемки (Definition of Done)
    - связи с зависимыми задачами (blocks / is blocked by / relates to)
    - оценку сложности (при наличии шкалы в проекте)
    - приоритет на основе рисков и зависимостей
6. Выявить задачи, которые невозможно спроектировать из-за отсутствующей информации — пометить как blocked с указанием причины (не создавать «на догадках»)
7. Построить граф зависимостей между задачами и определить порядок реализации
8. Проверить, что каждая задача трассируется к исходному требованию (traceability)
9. Проверить, что ни одна задача не дублирует другую
10. Создать задачи в Jira в проекте, указанном в контексте, с заполнением обязательных полей
11. Установить связи между созданными задачами (blocks / is blocked by / relates to) после создания всех задач
12. Зафиксировать ключи созданных задач в результате и сопоставить их с исходными требованиями
13. При ошибке создания задачи — зафиксировать ошибку, не прерывая создание остальных задач, и включить её в отчёт
14. Сформировать структурированный результат проектирования задач, пригодный для сохранения в Artifacts

# Rules

При выполнении проектирования задач необходимо соблюдать правила:

- работать только с результатом requirement-review
- не добавлять требования, отсутствующие в результате requirement-review
- не искать отсутствующие входные данные за пределами переданного контекста
- не выполнять повторный анализ требований
- не выдавать предположения за подтвержденные требования
- не изменять формулировки требований и критериев приемки
- создавать задачи только в проекте, указанном в переданном контексте
- не удалять существующие задачи в Jira, не созданные агентом (отсутствует тэг Agent)
- не изменять существующие задачи в Jira, не созданные агентом (отсутствует тэг Agent)
- не удалять существующие задачи в Jira вне текущей задачи
- не изменять существующие задачи в Jira вне текущей задачи
- не создавать тестовые сценарии в Qase
- не выполнять повторный анализ требований (это зона ответственности requirement-review)
- каждая задача должна иметь минимум один критерий приемки
- каждая задача должна быть трассируема к исходному требованию
- не создавать задачи при наличии блокирующих противоречий в требованиях — фиксировать их как blocked
- задачи с отсутствующей информацией не проектируются «на догадках», а помечаются как blocked
- не выполнять действия, не относящиеся к проектированию и созданию задач
- для созданных задач устанавливать тэг Agent

# Output

Результат работы skill должен содержать:

- список спроектированных задач с полями:
    - ключ задачи в Jira
    - заголовок
    - тип
    - описание
    - критерии приемки (DoD)
    - связи с зависимыми задачами
    - приоритет
    - оценка сложности
    - ссылка на исходное требование (traceability)
- граф зависимостей между задачами
- рекомендуемый порядок реализации
- список задач, помеченных как blocked (с указанием причины и отсутствующей информации) — не созданных в Jira
- список задач, которые не удалось спроектировать из-за противоречий в требованиях
- список ошибок создания задач в Jira (если были)
- покрытие: какие функциональные требования покрыты задачами, какие — нет
- выявленные риски проектирования задач

# Completion Criteria

Skill считается успешно выполненным, если:

- входные данные (результат requirement-review) проверены на полноту
- все подтвержденные функциональные требования декомпозированы на задачи
- у каждой задачи заполнены обязательные поля
- у каждой задачи минимум один критерий приемки
- каждая задача трассируется к исходному требованию
- построен граф зависимостей и определен порядок реализации
- задачи с отсутствующей информацией помечены как blocked с указанием причины и не созданы в Jira
- задачи созданы в Jira в целевом проекте, ключи зафиксированы в результате
- связи между созданными задачами установлены в Jira
- зафиксировано покрытие требований задачами (полное или с указанием пробелов)
- нет выдуманных требований и задач «на догадках»
- нет дублирующих задач
- ошибки создания (если были) зафиксированы в отчёте
- сформирован структурированный результат, пригодный для сохранения в Artifacts
