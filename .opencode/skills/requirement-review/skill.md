# Purpose

Выполнять систематический анализ требований перед их использованием для формирования задач разработки и проектирования тестовой модели.

# Inputs

Для применения skill необходимы:

- текст требований
- связанные с требованиями бизнес-правила
- критерии приемки

# Procedure

1. определить функциональность
2. выделить функциональные требования
3. выделить бизнес-правила
4. выделить ограничения
5. определить критерии приемки
6. определить зависимости в требованиях
7. выявить неоднозначности
8. выявить противоречия
9. определить отсутствующую информацию
10. сформировать структурированный результат анализа, пригодный для дальнейшего использования агентом

# Rules

При выполнении анализа необходимо соблюдать правила:

- не искать отсутствующие входные данные за пределами переданного контекста
- не добавлять отсутствующие бизнес-правила
- не выдавать предположения за подтвержденные требования
- не изменять текст требований
- не создавать задачи в рамках этого скила в Jira
- не создавать тестовые сценарии в Qase
- не выполнять действия, не относящиеся к анализу требований

# Output

Результат работы skill должен содержать:

- список выявленных функциональных требований
- бизнес-правила
- ограничения
- критерии приемки
- зависимости в требованиях
- найденные неоднозначности
- найденные противоречия
- отсутствующую информацию
- выявленные риски

# Completion Criteria

Skill считается успешно выполненным, если:

- входные требования проанализированы
- бизнес-правила и ограничения зафиксированы
- неоднозначности и противоречия либо выявлены, либо указано, что они не обнаружены
- отсутствующая информация зафиксирована
- нет выдуманных требований
- сформирован структурированный результат анализа
