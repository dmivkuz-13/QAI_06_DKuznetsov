## 2. Список задач

### 2.1 Созданные задачи

#### KAN-9 — Реализовать управление состоянием кнопки «Войти» (disabled до заполнения полей)
- **Тип:** Задача (10003)
- **Метки:** Agent, auth, ui
- **Приоритет:** High — *предварительное*, требует согласования (правила приоритизации в проекте не зафиксированы)
- **Оценка сложности:** не назначена — *предварительное*, требует согласования (шкала оценки в проекте отсутствует)
- **Трассировка:** FR-004 / REQ-AUTH-004 (CON-003, DEP-001)
- **Описание:** состояние кнопки «Войти» (disabled), пока не заполнены оба поля; изначально disabled; реактивируется при очистке полей; в disabled не инициирует submit. Ссылка на страницу требований и контекст зависимостей.
- **Критерии приёмки (DoD):**
  1. Кнопка «Войти» присутствует и изначально disabled.
  2. Остаётся disabled, если заполнено только одно из полей.
  3. Становится enabled только после заполнения обоих полей.
  4. При очистке любого поля возвращается в disabled.
  5. В disabled клик не вызывает submit.
- **Связи:** is blocked by KAN-2; relates to KAN-4; relates to KAN-1.

## 4. Blocked-задачи (не созданы в Jira)

- **Статус:** BLOCKED — не создана в Jira «на догадках».
- **Причина:** блокирующее противоречие **C-001**. REQ-AUTH-004 требует disabled-кнопку, пока не заполнены оба поля, поэтому сценарий «при попытке отправки пустой формы» (REQ-AUTH-007) недостижим в описанной конфигурации. Триггер валидации заполненности не определён (AMB-008).
- **Решение оркестратора:** FR-007 — blocked, отдельную задачу не создавать.
- **Примечание:** фрагмент поведения REQ-AUTH-007 присутствует в описании KAN-4, однако само событие-триггер неверифицируемо до решения C-001. Не считается подтверждённо покрытым.
